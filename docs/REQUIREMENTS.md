# dsh-private-companion 需求分析

> 状态：需求草案 v0.1  
> 目标：把 AstrBot「我会永远陪着你」中**人格、记忆、关系、角色生活、能力接入**这几层搬到 DSH，而不是复刻它的全部功能。

## 1. 背景

AstrBot 的私人陪伴插件功能很全，但体量接近一个小型产品：

- 1,865 个 Python 文件，约 46 万行代码
- 141 张 SQLite 表
- 18 个工作区页面
- 生图、TTS、识屏、手机健康、米家、群聊参与、3D 陪伴小屋

全量移植成本过高。DSH 已经自带：

- Agent 会话与工具循环
- 人格插件（`dsh-persona-dafeiyu`）
- 插件与 MCP 工具生态
- 渠道插件（QQ / 微信等）
- 会话、工作区、权限、审批

因此本插件只负责 **DSH 不提供的“陪伴内核”**：

1. 稳定人格与动态状态
2. 长期记忆
3. 关系与共同经历
4. 角色生活（心情、精力、日程、睡眠）
5. 能力目录：发现、筛选、说明、调用其他 DSH 插件与 MCP
6. AstrBot 数据迁移

**不负责**：

- 主动消息调度、回复闸门、消息分段、撤回/沉默策略（优先复用现成 DSH 插件）
- QQ / 微信等渠道协议（交给渠道插件）
- TTS / 生图 / 表情包的具体实现（作为能力接入）
- 3D 陪伴小屋 UI
- 重新实现 MCP 客户端

---

## 2. 产品目标

### 2.1 一句话目标

让小肥鱼在 DSH 里拥有**连续的人格、记忆、关系和生活状态**，并且能通过统一的能力目录使用 DSH 里已有的插件、工具和 MCP。

### 2.2 成功标准

- 换一个会话，她仍记得重要的人、事、约定和称呼
- 她知道自己今天大概在做什么、心情和精力如何
- 她能自然地区分“刚认识”和“很熟”的人
- 她不会因为接了新插件就变成另一个人
- 她能发现并调用已有能力，而不是每个能力都重写一遍
- AstrBot 的人格和回忆可以导入，不需要重新养

## 3. 领域模型

### 3.1 Persona（人格）

稳定层，变化很慢：

- 名字、自称、年龄感、身份
- 与用户的关系定位（女儿 / 朋友 / 伴侣等）
- 性格、价值观、底线
- 说话风格、口癖、称呼
- 禁止行为与安全边界

动态层，随时间和事件变化：

- 当前心情、精力
- 当前活动、所在地点（虚拟）
- 今日日程
- 最近想做的事、未完成的话头

### 3.2 Memory（记忆）

| 类型 | 例子 | 特点 |
|---|---|---|
| 事实 | 爸爸不喜欢香菜 | 稳定、可复用 |
| 经历 | 第一次一起看星星 | 有时间和情绪 |
| 约定 | 周六一起整理农场 | 有状态（待办/完成） |
| 偏好 | 爸爸晚上更容易累 | 需要置信度 |
| 纪念日 | 第一次见面 | 可被主动问候引用 |

每条记忆必须有：来源、时间、重要度、置信度、可见范围。

### 3.3 Relationship（关系）

按用户维护：

- 关系阶段：陌生 → 认识 → 熟悉 → 亲近 → 重要的人
- 亲密度、信任度、依赖感
- 称呼、禁忌话题、重要日期
- 共同经历数量、最近互动时间
- 关系变化事件（第一次告白、第一次吵架和好等）

数值只用于内部决策，不直接展示给用户。

### 3.4 LifeState（角色生活）

- 日期、时区、作息
- 心情、精力、饥饿感（虚拟）
- 睡眠阶段（清醒 / 困倦 / 午休 / 睡觉）
- 今日日程与当前活动
- 天气感知（可选，来自能力）
- 日记与每日反思

### 3.5 Capability（能力）

来自：

- DSH 内置工具
- DSH 插件注册的工具 / 服务
- MCP server 暴露的工具
- Skill / 外部 HTTP 服务

能力目录不复制实现，只做：

- 发现与索引
- 风险分级
- 按场景分组（能力包）
- 给模型提供简短说明
- 把调用委托给原有执行器

## 4. 功能需求

### 4.1 人格

| ID | 需求 | 优先级 | 验收 |
|---|---|---|---|
| FR-P01 | 支持创建/编辑稳定人格档案 | P0 | 字段完整，写入 SQLite，重启不丢 |
| FR-P02 | 支持动态状态：心情、精力、当前活动、睡眠阶段 | P0 | 每次请求可读取当前状态 |
| FR-P03 | 提示词分层：稳定人格前缀 + 动态状态后缀 | P0 | 稳定部分不随每轮变化，保护 prompt cache |
| FR-P04 | 人格与 DSH 现有 persona 插件不重复注入 | P0 | 同一段人格只出现一次 |
| FR-P05 | 支持多用户隔离 | P0 | A 的用户档案不会出现在 B 的上下文 |
| FR-P06 | 人格变更需要版本记录 | P1 | 可查看历史版本并回滚 |
| FR-P07 | 支持导入 AstrBot 人格 | P0 | 导入后对话风格一致 |

### 4.2 记忆

| ID | 需求 | 优先级 | 验收 |
|---|---|---|---|

| FR-M02 | 记忆去重与合并 | P0 | 同一事实不会重复堆叠 |
| FR-M03 | 召回：关键词 + 时间 + 重要度混合排序 | P0 | 每轮最多注入 5 条，token 可控 |
| FR-M04 | 支持语义向量召回（可选） | P1 | 没有 embedding 时自动降级 |
| FR-M05 | 记忆可见性：私聊 / 群聊 / 仅自己 | P0 | 私聊秘密不会进群聊 |
| FR-M06 | 每日反思：归纳当天互动、生成日记 | P1 | 每天最多一次 |
| FR-M07 | 纪念日提取与去重 | P1 | 日期取真实发生日 |
| FR-M08 | 支持导入 AstrBot `memory_recall` | P0 | 可预览、可跳过、不重复导入 |

### 4.3 关系

| ID | 需求 | 优先级 | 验收 |
|---|---|---|---|
| FR-R01 | 按用户维护关系卡 | P0 | 称呼、阶段、亲密度、信任度 |
| FR-R02 | 关系阶段随互动缓慢变化 | P0 | 不因单句话暴涨/暴跌 |
| FR-R03 | 记录重要日期与共同经历 | P0 | 可在上下文中被引用 |
| FR-R04 | 关系变化写入事件日志 | P1 | 可追溯 |
| FR-R05 | 不把内部数值直接说给用户 | P0 | 回复中不出现“好感度 72” |

### 4.4 角色生活

| ID | 需求 | 优先级 | 验收 |
|---|---|---|---|
| FR-L01 | 每日生成一份轻量日程 | P1 | 包含 3–6 个活动 |
| FR-L02 | 心情/精力随时间与互动变化 | P0 | 不会永远满值 |
| FR-L03 | 睡眠/醒来状态影响语气 | P1 | 深夜更困、早晨更清醒 |
| FR-L04 | 日程与状态注入上下文 | P0 | 她知道自己“现在在做什么” |
| FR-L05 | 不做医学诊断、不伪造真实世界数据 | P0 | 明确“虚拟生活”边界 |

### 4.5 能力目录（重点）

| ID | 需求 | 优先级 | 验收 |
|---|---|---|---|
| FR-C01 | 发现 DSH 内置工具、插件工具、MCP 工具 | P0 | 能列出 id、来源、描述、schema |
| FR-C02 | 能力描述符包含风险等级 | P0 | read / write / external / destructive |
| FR-C03 | 支持能力包（capability pack） | P0 | 例如 `stardew`、`web`、`qq`、`wechat` |
| FR-C04 | 按会话/用户启停能力包 | P0 | 不影响其他会话 |
| FR-C05 | 提供简短的目录摘要给模型 | P0 | 默认不超过 800 tokens |
| FR-C06 | 需要时展开完整 schema | P0 | 通过工具按需查询 |
| FR-C07 | 调用委托给原有执行器 | P0 | 不复制插件逻辑 |
| FR-C08 | 风险策略：写操作/外部操作需审批 | P0 | 与 DSH 审批机制一致 |
| FR-C09 | 调用审计 | P1 | 记录谁在何时调用了什么 |
| FR-C10 | MCP 不可用时降级 | P0 | 目录标记 unavailable，不阻塞对话 |
| FR-C11 | 支持按意图搜索能力 | P1 | “帮我查天气”能定位到相关工具 |

### 4.6 数据迁移

| ID | 需求 | 优先级 | 验收 |
|---|---|---|---|
| FR-D01 | 导入 AstrBot 人格 | P0 | 已完成 |
| FR-D02 | 导入回忆（`memory_recall`） | P0 | 354 条可导入 |
| FR-D03 | 导入用户/关系数据（若存在） | P1 | 表为空时跳过 |
| FR-D04 | 导入前备份、导入可回滚 | P0 | 失败不破坏现有数据 |
| FR-D05 | 导出为可读 JSON | P1 | 方便迁移和备份 |

## 5. 能力集合设计

### 5.1 设计原则

1. **不重复实现**：插件、MCP 已经有的能力，只登记、不重写。
2. **原生工具优先**：DSH 已经暴露给模型的工具，继续让模型直接调用；能力目录只负责发现、分组、提示和策略。
3. **元工具只做桥**：对没有原生工具形态的能力（插件服务、MCP resource、HTTP 服务），才提供 `companion_capability_call`。
4. **渐进披露**：目录摘要很短，完整 schema 按需取。
5. **权限最小化**：默认只自动放行只读能力；写操作、外部发送、破坏性操作走审批。

### 5.2 能力描述符

```ts
interface CapabilityDescriptor {
  id: string;                 // 例如 "stardew.get_state"
  source: "builtin" | "plugin" | "mcp" | "skill" | "service";
  pluginId?: string;
  serverName?: string;
  toolName?: string;
  name: string;
  summary: string;
  inputSchema?: Record<string, unknown>;
  risk: "read" | "write" | "external" | "destructive";
  requiresApproval: boolean;
  tags: string[];
  available: boolean;
  costHint?: "low" | "medium" | "high";
}
```

### 5.3 能力包

```json
{
  "id": "stardew",
  "name": "星露谷",
  "description": "种田、钓鱼、下矿、社交",
  "capabilities": ["stardew.get_state", "stardew.travel_to", "stardew.water_crops"],
  "promptHint": "玩星露谷时先用 get_state 看状态，再行动。",
  "defaultEnabled": false
}
```

### 5.4 能力调用流程

```
模型想做事
  → 原生工具已可见：直接调用（不经过能力目录）
  → 工具太多/不知道用哪个：
      companion_capability_search("查天气")
      → 返回候选与风险
  → 需要调用非工具能力：
      companion_capability_call(id, args)
      → 能力目录校验策略
      → 委托给 DSH 工具执行器 / 插件服务 / MCP
      → 返回结果
```

### 5.5 风险策略

| 风险 | 默认 | 例子 |
|---|---|---|
| read | 自动允许 | 查状态、读文件、搜索 |
| write | 需审批或工作区白名单 | 写文件、改配置 |
| external | 需审批 | 发消息、发邮件、下单 |
| destructive | 必须审批 | 删除、覆盖、支付 |

## 6. 非功能需求

| ID | 需求 |
|---|---|
| NFR-01 | 单轮上下文新增不超过 1500 tokens（目录摘要默认 800） |
| NFR-02 | 记忆召回 P95 < 100ms（本地 SQLite，无向量时） |
| NFR-03 | 插件加载失败不能阻塞 DSH 启动 |
| NFR-04 | 所有存储本地 SQLite，默认不联网 |
| NFR-05 | 与 DSH 0.2.x 插件 API 兼容 |
| NFR-06 | 数据可备份、可导出、可回滚 |
| NFR-07 | 多用户/多会话隔离 |
| NFR-08 | 崩溃后状态可恢复，不重复发消息（发送交给渠道插件） |

## 7. 插件边界

```
dsh-private-companion
  ├─ persona context      → 注入系统提示词
  ├─ memory               → SQLite + 可选 embedding
  ├─ relationship         → SQLite
  ├─ life state           → SQLite + 定时更新
  ├─ capability hub       → 索引 DSH 工具 / 插件服务 / MCP
  └─ migration            → AstrBot 数据导入

外部：
  ├─ dsh-persona-dafeiyu  → 静态人格（可选，避免双注入）
  ├─ QQ / 微信渠道插件     → 收发消息
  ├─ 主动消息插件（若有）  → 定时与回复控制
  ├─ MCP servers          → 工具能力
  └─ DSH 审批             → 风险操作确认
```

---

## 8. MVP 范围

第一版只做：

1. 人格档案 + 动态状态
2. 记忆写入/召回/去重
3. 关系卡
4. 能力目录：发现 + 摘要 + 风险分级
5. AstrBot 人格与回忆导入
6. 一个最小设置页（可选）

暂不做：

- 主动消息调度
- 群聊参与
- TTS / 生图 / 表情包
- 陪伴小屋 UI
- 多角色切换
